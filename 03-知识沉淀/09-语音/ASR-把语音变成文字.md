# ASR-把语音变成文字

> 课程 18 最小知识版 · 2026-08-19

## 背景问题

Agent 要接收真实用户输入时，很多场景是语音而不是文字：微信语音、语音助手、会议纪要。如果 Agent 只接受文字，用户就必须手动打字。不解决这个问题，多模态 Agent 的“耳朵”就是缺失的。

## 演进过程

早期靠人工规则和有限词表，识别率低。后来进入统计模型（GMM-HMM），再到深度学习端到端模型。现在以 Whisper、FunASR 为代表，可以直接“音频特征 → 文字”，不再需要复杂的音素对齐流程。

## 核心思想

本质是序列到序列的转换：把语音波形翻译成文字序列。工程链路为：采样数字化 → 分帧 + FFT → 特征（FBank/MFCC）→ ASR 模型 → 文字。工程上通常不手写特征提取，直接调用开源模型。

## 算法 / 系统位置

属于“语音支撑”层，是 Agent 的输入接口，位于链路最前面：语音 → ASR → 文本 → Agent / RAG。质量用 WER/CER 衡量：编辑距离 / 总字数；中文用 CER（字符错误率）更合适。

## 真实案例

微信语音转文字、抖音自动字幕、会议纪要工具都依赖 ASR。在项目 3 中，ASR 把语音提问转成文本，再进入 Agent 和 RAG，是项目 3 的第一个输入环节。

## 面试视角

面试官常问：ASR 和 OCR 的相同点（都是把非文本输入转成文本）；WER/CER 怎么算；识别不准怎么排查（先看音频质量：噪声、方言、多说话人，再看模型与语言配置）；为什么中文用 CER 而不是 WER（中文没有空格分词）。

## 实践任务

用 Whisper 把一个中文语音文件转成文字，记录 CER 和一个 Bad Case（方言、噪声、同音字等）。产出：转写文本、CER 分数、失败原因。
