# RAG 在 Agent 应用岗中的位置

> 第一篇七段式技术笔记
> 2026-08-13

## 背景问题

大模型只能基于训练时见过的数据回答，无法访问企业内部文档、最新知识或个人数据。直接让模型回答，容易出现过时和幻觉。RAG 解决的核心问题是：怎么让模型在回答时，拿到真实的、可追溯的外部知识。

## 演进过程

最早是只靠 Prompt 让模型回答；后来用微调把知识塞进模型，但训练贵、更新慢、容易过拟合。RAG 的出现让知识从“存在模型里”变成“存在数据库里”：查询时检索，回答时引用。再往后出现了 GraphRAG、Agent + RAG，检索不再是单次查文档，而是由 Agent 决定查什么、怎么查、要不要再查。

## 核心思想

一句话：先用检索找到相关资料，再把资料放进上下文让模型生成答案。

标准链路是：文档切块 → 向量化 → 向量检索 → 重排 → 拼进 Prompt → 生成 → 引用来源。

## 算法 / 系统位置

RAG 位于 Agent 应用的整体链路中：

```
用户输入 → Agent 理解意图
        → 调用检索工具（RAG）
        → 取回文档/知识
        → LLM 生成
        → 引用溯源
```

它依赖 Embedding 模型、向量数据库、重排模型和后端服务，属于 Agent 的“工具/知识层”，不是模型本身。

## 真实案例

企业知识库问答是最常见的场景：员工问“报销流程是什么”，系统先检索公司制度文档，再回答并附上文档链接。合肥和一线城市的大量 Agent 应用岗 JD 都把 RAG 列为必需技能，要求会分块、Embedding 选型、混合检索、重排和向量库实践。

## 面试视角

面试官常问：

- 为什么要 RAG，不用微调？
- Chunking 怎么切，切多大？
- Embedding 模型怎么选？
- 向量检索和关键词检索各有什么问题，为什么要混合检索？
- 检索结果不准怎么办？
- RAGAS 怎么评测？幻觉怎么缓解？
- 知识更新了，检索结果如何同步？

## 实践任务

用公开文档建一个小知识库，完成最小 RAG Demo：

1. 选 5–10 篇 Markdown/PDF 文档
2. 切块 → 生成 Embedding → 存入 FAISS/Chroma
3. 写一个查询接口，返回答案和引用
4. 手动准备 10 个问题，统计回答正确率，记录 3 个 Bad Case

完成标准：能讲清每步为什么这么做，能指出至少 3 个失败场景。
