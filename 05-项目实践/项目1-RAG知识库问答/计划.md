# 项目 1 执行计划（企业级 RAG，法规/合规域）

> 领域：中国金融 / 资本市场监管法规 + 上市公司合规公告（公开数据，模拟企业合规场景）。
> 为什么选它：强监管、文档复杂（PDF/表格/长文/多版本）、有多跳与引用需求，能逼出企业级 RAG 的全部优化点。
> 用法：每完成一个里程碑，在下方「动态调整记录」里追加一行；计划本身按实际情况随时改，不僵化。

## 总目标

一个企业级 RAG 知识库问答系统：能对监管法规、上市公司公告、规则条文做精准检索、带引用回答、可评测、有权限与审计、可一键部署。

## 数据域与来源（公开）

- 法规 / 规章制度：国家法律法规数据库、证监会 / 交易所（沪深）规则、国务院 / 部委规章、地方性监管规定。
- 上市公司合规公告：巨潮资讯网（cninfo）公开的招股书、年报、重大事项公告（用于深挖表格、长文、跨文档）。
- 目标：先拿 20–30 篇有代表性、覆盖「条文 / 表格 / 长文 / 多文档」的公开文档，建立基线；后续可扩到 50+。

## 里程碑

### M0 数据源锁定（本周）

- 任务：选定 20–30 篇公开文档，覆盖三类：法律法规、监管规则、上市公司公告。
- 交付：`data/manifest.csv`（记录每篇来源 URL、标题、类型、发布方、日期）+ 原文放入 `data/raw/`。
- 完成标准：每篇能追溯到公开来源，且人工能读出核心内容。
- 记录：`数据源清单`、`每篇的类型/长文/表格`。

### M1 解析与清洗

- 任务：多格式解析（PDF / PDF 扫描件 / Word / 网页 / 表格），保留表格结构；清洗、去重、纠错；生成元数据（来源、类型、效力层级、日期、部门）。
- 交付：`scripts/ingest_parse.py` → `data/documents.json`（结构化成 `{id, source, type, date, level, text, meta}`）。
- 评测：人工抽 20 段校验是否保留关键信息、表格是否复原。
- 完成标准：关键条文、条款号、表格数据不丢。

### M2 分块 + Embedding + 索引

- 任务：智能分块（尊重标题层级、父子块、自适应 + 重叠）；选中文/领域 Embedding；建向量索引 + 全文索引。
- 交付：`scripts/ingest_index.py` → `data/index/`（Chroma / FAISS + 全文索引）。
- 评测：固定 10 问，看 Recall@K；对比不同 chunk_size。
- 完成标准：固定问题集上召回能命中正确答案所在文档。

### M3 检索 + 重排

- 任务：混合检索（向量 + BM25）、元数据过滤、查询改写 / 多路召回、（进阶）会话上下文改写；两阶段重排（cross-encoder）。
- 交付：`app/retriever.py`。
- 评测：Recall@K、MRR、NDCG，对比「纯向量 vs 混合 vs 混合+重排」。
- 完成标准：混合 + 重排相对纯向量有明显提升（有数据）。

### M4 生成 + 引用 + 拒答

- 任务：Prompt 约束（只依检索内容答、无依据就拒答、给引用）；引用溯源；幻觉控制；（进阶）多跳分解。
- 交付：`app/generator.py` + `/ask` 接口雏形。
- 评测：RAGAS 忠实性、答案相关性；引用命中率；幻觉占比。
- 完成标准：回答有依据、能溯源、不乱编。

### M5 评测闭环 + Bad Case

- 任务：自建 50+ 问答（含多跳、表格、条文类）；RAGAS 四指标（忠实性、答案相关性、上下文精度、上下文召回）；失败定位（检索 vs 生成）；做一轮修复记录前后对比。
- 交付：`eval/run_eval.py` + `eval/report.md`。
- 完成标准：准确率 ≥ 80%，并写明提升了哪一类、幅度多少。

### M6 企业级工程 + 部署

- 任务：权限隔离（身份不同不越权）、增量更新 / 过期、审计留痕、可观测（trace）、FastAPI + Docker Compose、P95 / 成本指标。
- 交付：`app/`、`Dockerfile`、`docker-compose.yml`、权限/审计/观测模块。
- 完成标准：`docker compose up` 一键启动，权限用例如期通过，P95 < 3 秒。

### M7 进阶（可选）

- Agentic RAG：多跳拆解、按需检索、工具调用、失败自评重试。
- Graph RAG：跨文档实体关系、多跳推理（针对"政策关联""交叉引用"）。

## 评测基线（贯穿）

- 离线：RAGAS 四指标 + 自建问答集。
- 在线：业务成功率、引用命中、P95、Token / 成本。
- 失败定位：先看 Retrieval（有没有召回对的），再看 Generation（召回对但答偏）。
