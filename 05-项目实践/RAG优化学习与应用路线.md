# RAG 优化学习与应用路线（企业级）

> 目标：把 RAG 从「能跑」做到「好用、可信、可上线」，并把每个优化点都学会、用上、能讲。
> 原则：每一环都有「做什么 → 为什么 → 怎么落地 → 怎么评测 → 优先级」。
> 整个路线挂在项目 1 上：项目 1 每完成一个优化点，就在此打钩并记录对比数据。

## 一、完整管线（企业级）

```
多源文档 → 解析(OCR/表格/版面) → 清洗 → 智能分块 → 元数据 → Embedding → 索引(向量+全文)
                                                                          ↓
用户提问 → 查询改写/意图 → 混合检索(向量+关键词) → 元数据过滤 → 多路召回
                ↓
        两阶段重排(cross-encoder) → 组装上下文 → Prompt → LLM 生成 → 引用溯源 → 拒答/幻觉控制

工程支柱：权限隔离 · 增量更新/过期 · 审计留痕 · 延迟/成本 · 可观测 · 评测回归
```

## 二、优化细节清单

### 1. 数据与解析（决定上限）

- 多格式：PDF / 扫描件 / Word / 网页 / 表格 / 图片。PDF 要处理表格、双栏、多页。
- 解析方案：PaddleOCR / MinerU / 版面分析；表格要保留二维结构，不能压成一行。
- 清洗：去重、去噪、去模板页脚、纠错；记录来源、版本、部门、类型、时间等元数据。
- **为什么重要**：解析烂，后面全部白做（垃圾进垃圾出）。
- **评测**：抽 20 段人工校验解析后的文本是否保留关键信息、表格是否复原。

### 2. 分块（Chunking，最常见失败点）

- 尊重自然结构：标题层级、段落、句子；Markdown/JSON 文档按结构分块（MarkdownHeaderTextSplitter）。
- 自适应/语义分块：按语义相似度在边界切断；长文用小分块 + 父子块，保留上下文。
- 重叠：15% 左右，避免切断关键句；对比不同 chunk_size 的召回差异。
- 上下文扩展：检索到块后，带上相邻块或父块，提升生成信息量。
- **评测**：用固定问题集看不同分块下的召回命中率，选最佳配置。

### 3. Embedding 与索引

- 选中文/领域适配模型（>= 国内主流：bge / GTE / 智源等）；看维度、分数分布。
- 向量库：Chroma / FAISS / Milvus / pgvector；要支持标量过滤（metadata 过滤）。
- 索引：HNSW 参数、量化（PQ/SQ）降成本；同时建全文索引（BM25）以备混合检索。
- 区分向量检索（语义近似）与关键词/全文（精确匹配，如型号、人名、条款号）。

### 4. 检索（召回质量是核心）

- 混合检索：向量 + BM25，加权融合（RRF / 加权/线性），解决「文字差异大但意思近」和「精确词」两类问题。
- 元数据过滤：先按部门/版本/类型/时间过滤，再向量检索，缩小候选、提升精度。
- 查询改写/多路召回：把用户问题改写、拆成多个查询（同义、术语、拆子问题），多路召回后合并。
- 会话上下文：多轮对话时把历史合并进查询，避免「它」「那个」指代丢失。
- **评测**：Recall@K、MRR、NDCG；对比纯向量 vs 混合的差异。

### 5. 重排（Rerank）

- 两阶段：先召回 top-k（如 50），用 cross-encoder 重排取 top-n（如 5）。
- 常用：GTE-Rerank / bge-reranker；重排比单纯加向量检索提升明显。
- **评测**：重排后 top-5 的命中率/准确率变化（用固定问题集比 Recall@5 前后）。

### 6. 生成与幻觉控制

- Prompt：明确「只依据检索内容回答」「没有依据就说明无法回答」「给出引用」。
- 引用溯源：每条回答标注来自哪篇文档哪一句；增强可信与可审计。
- 拒答机制：检索置信度低或与问题无关时，礼貌拒答，而非编造。
- 多跳/复杂查询：一个问题的答案分散在多篇文档，需分解 + 多次检索（进阶 Agentic RAG）。
- **评测**：忠实性（回答是否都来自上下文）、答案相关性、引用命中率、幻觉占比。

### 7. 知识库工程（企业级分水岭）

- 权限隔离：索引层面打权限标签，回答时按当前身份过滤，防越权泄漏。
- 增量更新/过期：文档更新后能重建/作废对应索引，不残留旧版本。
- 审计留痕：记录谁在什么时间问了什么、用了哪些文档、答了什么。
- 版本/多租户：多部门、多版本共存，元数据隔离。
- **评测**：权限用例（不同身份跑同一套问题，校验不越权）、更新用例（改文档后答案跟随）。

### 8. 评测与可观测

- 离线评测：RAGAS 四指标（忠实性、答案相关性、上下文精度、上下文召回）+ 自建 50+ 问答集。
- 在线指标：业务成功率、用户点赞/纠错、回答延迟 P95、Token 成本。
- 失败定位：区分「检索失败（没召回对的）」还是「生成失败（召回对但答偏）」，用 trace 定位。
- 回归：每次改动重新跑同一套评测集，防止越改越差。
- 可观测：记录检索链路的 trace（查询、召回、重排、上下文、生成、引用）。

## 三、演进路径（面试最能讲）

```
Naive RAG（能跑）→ Advanced RAG（混合检索/重排/查询改写/元数据）
→ Enterprise RAG（权限/增量/审计/拒答/可观测）
→ Agentic RAG（多跳分解、按需检索、工具调用、自评重试）
→ Graph RAG / 知识图谱增强（跨文档实体关系、多跳推理）
```

简历与面试的发力点是：你从 Naive 到 Enterprise 每一步为什么做、结果提升多少、踩了什么坑。

## 四、里程碑映射（对应项目 1）

| 里程碑 | 要落地的优化 |
| --- | --- |
| M1 数据准备 | 多格式解析、清洗、智能分块、元数据、chunk 对比 |
| M2 向量检索 | Embedding 选型、向量+全文索引、召回评测 |
| M3 完整问答 | 混合检索、元数据过滤、重排、查询改写、引用、拒答 |
| M4 评测 | RAGAS 四指标、自建集、失败定位（检索 vs 生成） |
| M5 部署 | FastAPI、Docker、权限、审计、可观测、延迟/成本 |
| M6 迭代 | Bad Case 修复一轮、增量更新/过期、Agentic/多跳 |

## 五、面试高频点

- 为什么检索不全 / 答非所问：分块、检索（向量 vs 混合）、重排、评测，逐层排查。
- 怎么防幻觉：Prompt 约束 + 拒答 + 引用溯源 + 忠实性评测。
- 企业级和 demo 的区别：权限、增量更新、审计、可观测、评测闭环、成本/延迟。
- 多跳/复杂查询：Agentic RAG、查询分解、多路召回、Graph RAG。
- 指标：RAGAS 四指标、Recall@K、MRR/NDCG、业务成功率、P95、成本。
