# 项目 1：RAG 知识库问答

> 目标：做一个完整、可评测、可部署的 RAG 知识库问答系统，作为 Agent 应用岗和算法岗的共同作品集项目。

## 一句话

用户提问，系统从知识库中检索相关资料，生成带引用的回答。

## 成功指标

- 自建 50 条测试问答，回答准确率 ≥ 80%
- 每条回答都能溯源到文档引用
- 查询接口 P95 延迟 < 3 秒
- 能用 `docker compose up` 一键启动
- 至少完成 1 轮 Bad Case 修复并记录对比

## 系统链路

```
文档 → 清洗 → 分块 → Embedding → 向量库
                                      ↓
用户提问 → 意图理解 → 混合检索 → 重排 → LLM 生成 → 引用溯源
```

## 技术栈

- 后端：FastAPI
- 向量库：FAISS 或 Chroma（熟悉后可换 Milvus/pgvector）
- 框架：LangChain 或 LlamaIndex
- 模型：Embedding + 一个 LLM API（Qwen/DeepSeek/OpenAI 兼容）
- 部署：Docker Compose
- 评测：RAGAS + 人工标注集

## 数据

没有真实业务数据，使用公开数据，例如：

- 公司公开制度文档 / 产品文档
- 开源项目 README 和技术文档
- 行业白皮书 / 公开教材
- 自己整理的中文知识库

## 里程碑

### M1：数据准备（第 1–2 周）

- 选 20–50 篇文档
- 清洗：去重、去噪、统一格式
- 分块：比较不同 chunk size，记录效果

### M2：向量检索（第 3–4 周）

- 选 Embedding 模型
- 建向量库，完成召回
- 手动测试 10 个问题，记录召回效果

### M3：完整问答（第 5–6 周）

- 检索 → 重排 → Prompt → LLM 生成
- 输出引用来源
- 增加混合检索：向量 + 关键词

### M4：评测（第 7–8 周）

- 自建 50 条问答
- 用 RAGAS 评测：忠实性、答案相关性、上下文相关性
- 记录准确率、失败问题

### M5：部署（第 9–10 周）

- FastAPI 接口：`/ask`
- Docker Compose 一键启动
- 日志、健康检查、错误处理

### M6：迭代（第 11–12 周）

- 分析 Bad Case，做一轮修复
- 对比修复前后指标
- 写项目复盘

## 面试叙事

1 分钟版：这是一个知识库问答系统，用 RAG 解决模型不知道私有知识的问题，支持混合检索和引用溯源，50 条评测准确率 80%+，Bad Case 分析后把 X 类问题从 Y% 提升到 Z%。

5 分钟版：按「业务 → 数据 → 分块 → 检索 → 重排 → 生成 → 评测 → 部署 → 迭代」讲，每个环节说清选择和替代方案。
