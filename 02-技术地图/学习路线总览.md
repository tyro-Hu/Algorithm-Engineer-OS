# 算法工程师学习路线总览

> 最后更新：2026-08-24
> 目标：全国一线城市 + 合肥 · Agent 算法工程师（社招，工资优先），24 个月，兼顾工作
> 版本：v1.1（目标升级）
> 基准投入：每天 1–2 小时（约每周 8–12 小时），项目 + 基础 + 刷题并行
> 原则：项目驱动，先做出可演示能力，理论按需补

> 说明：下面「核心主线」是完整 24 个月算法路线；若你只想先跑通 Agent 应用，可先看下方「应用主线阶段」。
> 现实岗位要求见 `00-岗位与定位/Agent开发岗位调研-2026-08-24.md`（基于 50+ 真实 JD）。

## 核心主线

```
数学 → 机器学习 → 深度学习 → Transformer（从零）
    ↓
LLM 原理 + 推理 + RAG + Agent 应用（项目 1、2）
    ↓
多模态输入输出：OCR / ASR / TTS / VLM（项目 3）
    ↓
Post-training：SFT / LoRA / DPO / RLHF（算法项目 1）
    ↓
RL / Agentic RL（算法项目 2）
    ↓
AI Infra 与部署 + 面试冲刺
```

> 详细内容见 `02-技术地图/多领域学习路线.md`、`00-岗位与定位/启动决策摘要.md` 和 `总计划.md`。

## 阶段 0：定位与准备（第 1 月）

目标：确定岗位要求、搭好环境、跑通第一个最小 Demo。

- 读 `00-岗位与定位/市场岗位调研.md` 和 `启动决策摘要.md`
- 搭好 Python/PyTorch 环境，确认 Colab / 实验室 GPU 可用
- 用现有 RAG 经验跑通一个最小问答 Demo
- 开始 LeetCode：数组、哈希表

交付：
- 个人画像和启动决策
- 最小 RAG Demo
- 环境说明

## 阶段 1：Agent 工程核心（第 2–4 月）

目标：把 RAG 从 Demo 做成可评测、可部署的项目。

学习内容：
- LLM 原理：Prompt、Context Engineering、Token、模型选型
- RAG：分块、Embedding、混合检索、重排、引用、知识更新
- 向量库：FAISS、Chroma、Milvus、pgvector 至少精通一个
- 后端：FastAPI、Docker、PostgreSQL/Redis
- 评测：RAGAS、Bad Case、召回率、答案质量

交付：
- 项目 1：RAG 知识库问答（公开数据，端到端部署）
- 至少 2 篇七段式笔记

## 阶段 2：Agent 深潜（第 5–7 月）

目标：掌握 Agent 工程化，做出第二个作品集项目。

学习内容：
- Function Calling、Tool/API 封装
- MCP、LangGraph / LangChain / LlamaIndex / Dify 至少熟悉一个
- 记忆：短期上下文、长期记忆、向量记忆
- 多 Agent：规划、分工、通信、失败重试
- 安全：工具权限、沙箱、审批、审计
- 评测：任务成功率、延迟、成本、失败模式
- 框架成体系：LangChain / LangGraph 编排，Agent 可观测（trace、日志、失败恢复）
- MCP 工程化：不只是 Function Calling，会写 MCP Server / 工具封装 / 技能编排
- AI 编码工具工程化：Cursor / Claude Code / Opencode 融入日常开发
- 低代码平台了解：Dify / Coze

交付：
- 项目 2：Agent 自动化助手（工具调用 + 记忆 + 多 Agent）
- 项目复盘 1 篇

## 阶段 3：多领域支撑（第 8–10 月）

目标：让 Agent 能看、能听、能说，用多模态能力补齐 CV、语音、多模态知识。

学习内容：
- CV 支撑：OCR 集成，图片/文档解析进入 RAG
- 语音支撑：ASR 作为 Agent 输入，TTS 作为 Agent 输出
- 多模态支撑：VLM 做图片问答、图文检索
- 综合：语音提问 → OCR/ASR → RAG → 回答/语音播报

交付：
- 项目 3：多模态 Agent（至少整合 OCR + ASR + RAG）
- CV、语音、多模态各 1 篇入门笔记

## 阶段 4：面试冲刺（第 11–12 月）

目标：把项目、基础、刷题转换成一线城市/合肥的高薪社招机会。

内容：
- 算法题：高频题 + 错题重刷
- 理论题：LLM、RAG、Agent、后端、系统设计
- 项目叙事：3 个项目按「背景 → 难点 → 方案 → 结果 → 复盘」打磨
- 模拟面试：每周 1 次，录下复盘
- 简历：按 Agent 应用岗定制，突出工具调用、向量库、部署、指标

交付：
- 可投递简历
- 高频题题库 + 标准答案
- 3 轮模拟面试复盘

## 每周工作流

```
确定本周 1 个任务 → 最小实现 → 记录结果 → 刷 2–3 题
→ 每周日志 → 问题入库 → 下周调整
```

## 双线程穿插学习模式

应用产出线和算法地基线节奏不同，正好穿插，但各有「定义完成」。

- 线程 A（应用主线，产出）：先快速收掉课程 18（ASR，作为支撑能力），然后做作品集：项目 1 RAG → 项目 2 Agent → 项目 3 多模态。每个项目都要有可演示、可评测、可部署的完成品。
- 线程 B（算法地基，输入）：数学（线代/概率/微积分/优化）→ 机器学习 → 深度学习 → Transformer → LLM → Post-training / RL。每天固定一小步，用「视频画面 + AI 提问 + 代码」循环。
- 节奏（1–2 小时/天，默认）：约 60–75% 时间给 A（把项目推到里程碑），25–40% 给 B（每天一块地基）。每周至少一次整段时间（如周末 1.5 小时）做一次深挖，或把地基接进当前项目。
- 原则：A 必须“完成一个可演示的里程碑才换下一个”，不能永久半成品；B 必须“能用自己的话讲清楚才前进”，不能只刷视频。
- 刻意结合：做 RAG 时学向量/Embedding，做 Agent 时学 Function Calling，做后训练时必须懂 Transformer / RL。让地基直接服务于项目，项目反过来检验地基。
- 避免：别“两条都浅浅碰”，那样两头都半吊子。宁可一天只推进一条，也要推到底。
