# Agent 应用岗 vs 算法工程师：双线准备

> 2026-08-13

## 一、能力对比

| 能力 | Agent 应用开发工程师 | 算法工程师 |
| --- | --- | --- |
| LLM 原理 | 会选模型、会调 Prompt、懂上下文 | 能推导、能解释训练和推理 |
| RAG | 会做端到端，会优化检索 | 会设计评测，理解检索质量 |
| Agent | 必须熟练工具调用、MCP、多 Agent | 加分项，偏向 Agent 规划与训练 |
| 数学 | 够用即可 | 面试硬门槛 |
| 数据结构 | 中等题 | 中等偏难，数学题多 |
| 模型训练 | 了解 | 核心能力 |
| 系统设计 | 核心 | 一般 |
| 项目要求 | 产品可演示 | 训练/评测可复现 |

## 二、面试差异

### Agent 应用岗

- 项目深挖：为什么这样设计、挂了怎么办
- 系统设计：延迟、成本、可扩展、安全
- 工程题：API、数据库、缓存、部署
- 场景题：把业务问题拆成 Agent 流程

### 算法岗

- 数学推导：梯度、贝叶斯、SVD
- 模型原理：Transformer、损失、优化器
- 训练细节：过拟合、数据泄漏、A/B
- 论文/项目：有没有训练过、评测过、迭代过

## 三、长期阶段分配建议

> 2026-08-24 起主攻方向升级为 **Agent 算法工程师（LLM + Agent + RL + Post-training）**，
> 以下按 24 个月调整。Agent 应用开发保留为「落地载体」，算法岗成为主攻。

| 月份 | 主线 | 双线兼顾 |
| --- | --- | --- |
| 1–2 | 定位 + 数学 + Python 工程 | 启动 LeetCode |
| 3–6 | 机器学习 + 深度学习 + Transformer 从零实现 | 刷题补齐 |
| 7–9 | LLM 原理 + RAG + Agent 应用项目 | 沉淀笔记与项目复盘 |
| 10–12 | 多模态支撑（OCR/ASR/TTS/VLM）集成 | 跑通多模态 Agent |
| 13–18 | Post-training（SFT/LoRA/DPO/RLHF）+ RL/Agentic RL | 写可复现实验报告 |
| 19–24 | 部署 + 面试冲刺 | 算法岗侧重训练与评测；应用岗侧重落地 |

## 四、项目映射

| 项目 | 主要覆盖 |
| --- | --- |
| RAG 知识库 | Agent 岗：RAG + 后端；算法岗：检索评测 |
| Agent 自动化 | Agent 岗：核心 |
| 多模态 Agent | Agent 岗：多模态集成；算法岗：VLM/OCR/ASR 理解 |
| LoRA 微调 + 评测 | 算法岗：训练与评测；Agent 岗：微调加分项 |

## 五、结论

- 主攻升级为 **Agent 算法工程师（LLM + Agent + RL + Post-training）**，周期 24 个月
- 算法岗成为主攻；Agent 应用岗保留为落地载体，便于做出可演示作品
- 公共地基（数学/ML/DL/Transformer）不再是「有空再补」，而是前期核心任务
- 作品集 = 3 个应用项目 + 1 个「训练 + 评测」算法项目，保证算法岗能投
- 简历按岗位定制：应用岗突出落地，算法岗突出训练、评测与可复现
