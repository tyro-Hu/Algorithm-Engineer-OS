# 教学规则

> 本文件是教学规则库：所有讲解、课程设计、知识库维护行为都必须遵守。

## 规则清单

| 编号 | 规则 | 一句话 |
| --- | --- | --- |
| R-01 | 线性学习 | 学习要线性，后学的知识必须建立在前面的知识已学过的基础上 |
| R-02 | 代码详解 | 讲解代码必须带详细中文注释，说明「做了什么 + 为什么」 |
| R-03 | 示例偏好 | 前端示例用 Vue 3；算法示例默认 Python + PyTorch |
| R-04 | 一课一概念 | 每课最多引入 1–2 个新概念，按「故事 → 一句话定义 → 最小代码」三步讲 |
| R-05 | 案例辅助讲解 | 讲新概念必须配真实案例，类比只是辅助 |
| R-06 | 回答必反馈 | 凡要求学习者回答的问题，回答后必须给简短评价反馈，说明对/基本对/差一点以及一句修正 |

## R-01 线性学习

**一句话**：新概念必须先定义再使用；发现知识脱节，立即停下来补课。

执行要求：
1. 讲新概念前列出前置知识清单，缺了就补
2. 用术语前先一句话定义
3. 课程顺序 = 依赖顺序

检验方式：每课结束时检查本课用到的术语是否都能在之前的课里找到出处。

## R-02 代码详解

**一句话**：展示的代码必须带中文注释，解释「在做什么、为什么这么做」，不是逐句翻译。

执行要求：
1. 关键逻辑逐行/逐块注释
2. 新语法或 API 首次出现时在注释中说明
3. 学习者能脱离讲解、仅凭注释读懂代码

## R-03 示例偏好

**一句话**：算法示例默认 Python + PyTorch；需要前端示例时用 Vue 3。

理由：Python 是算法岗第一语言，PyTorch 是国内主流框架；Vue 3 是国内主流前端框架。

## R-04 一课一概念

**一句话**：每课最多引入 1–2 个新概念，用「故事 → 一句话定义 → 最小代码」三步讲。

执行要求：
1. 备课前写「本课新概念清单」，超过 2 个就拆课
2. 每个新概念必须走完三步，缺一步不算讲完
3. 能删的代码就删，只留能跑通核心概念的 5–15 行

检验方式：学习者能用 2–3 句自己的话复述本课新概念。

## R-05 案例辅助讲解

**一句话**：讲任何新概念，必须配一个真实开发案例，说清「用在哪、解决什么问题」。

案例优先级：
1. 自己的项目（`05-项目实践/`）
2. 知名产品里人人见过的功能（微信、淘宝、抖音等）
3. 公开数据集 / 开源项目

检验方式：学习者能说出「这个技术在我的哪个项目 / 哪个功能里用到了」。

## R-06 回答必反馈

**一句话**：凡是要学习者回答的问题，回答之后必须先做简短评价反馈，再继续下一课。

### 定义

- 学习者不知道自己的回答对不对，学习效果会打折扣
- 反馈必须包含：对 / 基本对 / 差一点 + 一句修正或补充
- 反馈要简短，不展开新知识

### 为什么

- 2026-08-14 用户明确要求：回答之后不知道对错
- 及时反馈能帮学习者确认理解、修正偏差，再进入下一课

### 执行要求

1. 每个检查问题之后，必须等学习者回答
2. 回答后先给评价，再讲下一课
3. 评价格式：`[对/基本对/差一点] + 一句修正`
4. 评价之后才更新课程进度

### 违反时的处理

发现没反馈就进入下一课 → 补上反馈并说明这一课未继续，等学习者确认。

### 检验方式

每一轮对话都能看到对上一课回答的评价，再看到下一课内容。
