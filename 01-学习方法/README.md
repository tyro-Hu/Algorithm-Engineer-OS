# 01-学习方法

本目录存放算法工程师学习的方法论，继承自系统架构师项目的学习体系，并做算法岗适配。

## 六问法

学习任何技术前，先回答六个问题，答不上来说明还没学到本质：

1. 为什么出现？解决了什么痛点？
2. 解决什么问题？问题的边界是什么？
3. 以前如何解决？演进脉络是什么？
4. 为什么现在需要它？时代背景和触发条件是什么？
5. 在算法研发流程 / 技术栈中处于什么位置？和上下游如何协作？
6. AI 时代有什么变化？它如何被大模型重塑？

## 七段式技术学习模板

所有 `03-知识沉淀/` 下的技术笔记统一使用：

> 背景问题 → 演进过程 → 核心思想 → 算法/系统位置 → 真实案例 → 面试视角 → 实践任务

详见 `技术学习模板.md`。

## 论文与案例

- 论文复现模板：`论文复现模板.md`
- 真实系统算法案例拆解：沿用架构师项目的「案例背景 → 八步拆解 → 关键决策 → 失败与权衡 → 可迁移结论」，但把「架构」替换成「算法链路：业务目标 → 数据 → 特征 → 模型 → 评估 → 上线 → 迭代」

## 项目复盘

- 每个作品集项目完成后一周内写复盘：`项目复盘模板.md`
- 复盘不是成绩单，是决策质量体检：记录约束、替代方案、失败原因、可复用经验

## 教学规则

本知识库同时用于「教自己」和「让 Codex 教自己」，遵守以下规则：

- R-01 线性学习：新概念必须先定义再使用，发现脱节立即补课
- R-02 代码详解：讲解代码必须带中文注释，说明「做了什么 + 为什么」
- R-03 示例偏好：前端示例用 Vue 3；算法代码默认 Python + PyTorch
- R-04 一课一概念：每课最多引入 1–2 个新概念，按「故事 → 一句话定义 → 最小代码」讲
- R-05 案例辅助讲解：新概念必须配真实案例（自己的项目或知名产品），类比只是辅助
- R-06 回答必反馈：凡要求回答的问题，回答后必须先给简短评价反馈，再继续下一课

详见 `教学规则.md`。
